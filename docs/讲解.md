# 讲解：这个工具在干什么

对着 `client_step1.cpp` 和 `sim_server.py` 看这一篇。

---

## 一、要解决的问题

一台真实设备（PLC、采集卡、传感器网关）会不停地往外面吐字节。它不会说"这是一帧""这是下一帧"——它就是一根管子，字节一个接一个地流。

上位机软件要做的第一件事，就是**把这条不断的流，切成一条一条有意义的记录**。

这个项目把这件事缩小到最小规模：一个程序假装是设备，一个程序假装是上位机。

---

## 二、两个程序，一条线

```
sim_server.py  ──TCP(127.0.0.1:9527)──▶  client_step1.exe
   假装设备                                  假装上位机
   每 100ms 发一帧                            收到字节就打印
```

- `sim_server.py`：监听 9527，有人连上来之后，每 100 毫秒发一帧。每 27 帧故意发一个坏帧。
- `client_step1.cpp`：连上去，把收到的字节按十六进制打出来。

先跑服务器，再跑客户端。服务器没人连的时候是阻塞等着的。

---

## 三、那 14 个字节，逐段拆

屏幕上会刷出这样的东西：

```
AA 55 08 00 00 00 98 08 3B 01 DC 05 C8 13
```

一共 14 个字节，按帧格式切四段：

| 位置 | 字节 | 含义 |
| --- | --- | --- |
| 1–2 | `AA 55` | **帧头**。一个固定的标记，用来在流里认出"一帧从这里开始" |
| 3–4 | `08 00` | **长度**。小端，`0x0008` = 8，表示后面数据区有 8 个字节 |
| 5–12 | `00 00 98 08 3B 01 DC 05` | **数据**。8 个字节 = 4 个 int16，每个 2 字节 |
| 13–14 | `C8 13` | **校验**。CRC16，算的是"长度 + 数据"这 10 个字节 |

数据区再拆成 4 个 int16（都是小端，低字节在前）：

| 字节 | 十六进制 | 十进制 | 意思 |
| --- | --- | --- | --- |
| `00 00` | 0x0000 | 0 | 序号 |
| `98 08` | 0x0898 | 2200 | 电压 |
| `3B 01` | 0x013B | 315 | 温度 |
| `DC 05` | 0x05DC | 1500 | 转速 |

**为什么是 14？** 2（帧头）+ 2（长度）+ 8（数据）+ 2（校验）= 14。长度字段只说数据区多长，帧头、长度、校验本身不算在里面——这是很常见的约定，但不唯一，换个协议可能算法不一样。

**小端是什么意思？** `0x0898` 这个数，写成字节时低位的 `98` 在前、高位的 `08` 在后。x86 的 CPU 就是这么存的，所以直接按内存打印出来就是这个顺序。看到 `98 08` 要能在脑子里翻成 `0x0898`。

## 四、`client_step1.cpp` 逐段讲

### 1. 给 socket 库上电

```cpp
WSADATA wsa{};
if (WSAStartup(MAKEWORD(2, 2), &wsa) != 0) { ... }
```

Windows 特有的一步。Linux 上写 socket 不需要这句，Windows 必须先告诉系统"我要用网络了"，把 Winsock 库加载进来。最后配一句 `WSACleanup()` 收尾。

### 2. 申请一条 TCP 通道

```cpp
SOCKET sock = ::socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
```

- `AF_INET`：IPv4
- `SOCK_STREAM`：流式套接字，也就是 TCP
- `IPPROTO_TCP`：协议用 TCP

返回的是一个整数句柄，后面所有操作都拿它指代这条连接。

### 3. 把地址和端口准备好

```cpp
sockaddr_in addr{};
addr.sin_family = AF_INET;
addr.sin_port = ::htons(port);
::inet_pton(AF_INET, host.c_str(), &addr.sin_addr);
```

- `inet_pton`：把字符串 `"127.0.0.1"` 转成 4 个字节的二进制地址
- `htons`：端口号要从"人的字节序"转成"网络的字节序"（大端）。忘了这一步就是经典 bug：连不上

### 4. 敲门

```cpp
::connect(sock, reinterpret_cast<sockaddr *>(&addr), sizeof(addr));
```

这一步会阻塞，直到对面接受或者失败。成功之后，这条通道就通了。

### 5. 收字节

```cpp
int n = ::recv(sock, buf, sizeof(buf), 0);
```

**这一行是整个项目的关键，也是第二三步存在的理由。**

`recv` 返回的 `n` 是这一次实际收到了多少字节。它可能是 14，可能是 28（两帧粘在一起），也可能是 7（半帧）。**它跟"帧"没有任何关系。**

现在这一版只是把 `n` 个字节打印出来；到第二步，就要把这些字节攒进一个缓冲区，自己去里面找 `AA 55`。

### 6. 收尾

```cpp
::closesocket(sock);
WSACleanup();
```

## 五、今晚要做到的三件事

1. **跑起来。** 两个终端，先服务器后客户端，看到刷屏。
2. **指着屏幕上那一行，说出四段分别是什么。** 帧头、长度、数据、校验，各自几个字节，长度是多少。
3. **改一个数，看结果变。** 比如把 `client_step1.cpp` 里 `packets >= 30` 改成 `5`，重新编译，看它收五包就退出。这一步是为了让你确认"我改的东西真的在起作用"。

编译命令：

```bat
g++ -std=c++17 -O2 client_step1.cpp -o client_step1.exe -lws2_32
```

---

## 六、几个容易卡住的地方

- **连不上**：服务器没起，或者端口对不上。先看到 `listening on 127.0.0.1:9527` 再去跑客户端。
- **994 / 10061 之类的错误码**：基本都是"对面没人"。
- **中文乱码**：终端编码问题，不影响结果，先不管。
- **改了代码没反应**：忘了重新编译。`.exe` 是编译出来的，改 `.cpp` 不会自动生效。
